# 市集兼职薪酬方案

根据排班、全勤底薪、固定出摊成本、商品成本和预计营业额，计算真实保本线，并设计最高不超过营业额5%的连续提成方案。

## 必填输入

收集以下十项：

```text
市集名称：
兼职日期：
每日约定兼职时间：
加班时薪：
整场全勤底薪总额：
预计每日营业额：
摊位费总额（无则填0）：
摊位装置费用总额（无则填0）：
出摊物流费用总额（含往返快递或运输，无则填0）：
主办方营业额抽成比例（无则填0）：
```

输入规则：

- 日期可为连续区间或日期列表。
- 每日约定兼职时间可统一填写，也可逐日填写。
- 默认从开始到结束全部计薪；如有不计薪休息，用户必须明确注明。
- “整场全勤底薪总额”覆盖全部约定兼职时间；没有加班时，基础工资按该金额计算。
- “加班时薪”只用于约定兼职时间之外、经双方确认的额外工作时间，不参与销售提成率推导。
- 加班工资＝实际加班工时×加班时薪；没有加班时，加班工资为0。
- 方案设计时若没有明确的预计加班安排，按0小时加班测算；实际发生加班后另行加到应付工资中，并重新计算实际盈亏。
- 预计每日营业额可为统一数值或逐日列表。
- 若营业额只有范围，询问采用哪个数值作为目标线，不自行取中位数或上限。
- “底薪”是整个活动全勤时的底薪总额，不是基础时薪。
- “摊位费”只计算不可退的实际成本；可退押金不计入成本。
- “摊位装置费用”默认按本场实际承担金额计算；可重复使用的装置若只分摊部分成本，必须由用户明确分摊金额。
- “出摊物流费用”只计算本场往返快递、货运或运输成本，不与顾客订单配送费重复计算。
- 固定出摊成本＝摊位费＋摊位装置费用＋出摊物流费用。
- 主办方抽成默认按扣除退款后的实际营业额计算；若存在保底抽成、阶梯抽成或其他口径，必须明确说明。

缺少必填项时，先补问，不生成正式文件。

## 默认参数

除非用户覆盖，采用：

```text
工作人数：1人
商品成本率：50%
商品毛利率：50%
最高提成率：营业额的5%
吃饭时间：计薪
业绩周期：整个市集总营业额
正常收款：计入业绩
退款：从业绩扣除
赠品、试吃：不计业绩
兼职自行打折：不允许
```

这些是项目经营默认值，不是法律结论。

## 每场必须写入的行为规则

以下内容是已确认的默认规则。以后每一场都写入店主版和兼职版，不另行发明扣款项目或扣款金额。

### 工作内容

招聘文案、店主版职责和兼职版职责都写上：

- 独立开摊、收摊；
- 独立看摊；
- 叫卖；
- 算账、收银、记账；
- 打包产品；
- 主动接待顾客，介绍和销售产品；
- 保持摊位整洁。

### 行为红线

1. 未经店主允许，不得打折，不得赠送产品。擅自打折的，少收金额从应付工资中扣除。擅自赠送的，按该产品当时标价从应付工资中扣除。
2. 不得迟到、早退。迟到或早退的时段不计薪。应付底薪＝底薪折合时薪×实际计薪工时。已经产生的销售提成仍按总营业额结算。本条不另加固定罚款。
3. 现场活动券、现场赠送产品，必须先与店主确认，不得自行决定赠送。未经确认赠出的，按当时标价从应付工资中扣除。
4. 若不认可本品牌手作，不要接下这份工作。接下后不得诋毁品牌。由此产生的不良影响，店主保留追责权利。本条不从工资中另扣固定金额。
5. 预报有雨时必须盖好雨布。店主要求把货物搬进仓库时必须配合。因未盖雨布，或不愿意搬仓，造成的货物损失，按受损货物售价从应付工资中扣除。工资扣完仍有差额的，差额另追。

红线可以出现在兼职版。不要在红线里写出商品成本率、毛利率、摊位费、装置费用、物流费用、主办方抽成或经营结余。

### 招募自我介绍

可直接发布的招聘文案必须要求应聘者在自我介绍中写明：

- 年龄；
- 性别；
- 是否待业；
- 兴趣爱好；
- 有没有摆摊经验。有的话，写明在哪里摆过、卖过什么。

## 工作流程

1. 规范化日期、每天起止时间、休息时间和预计营业额。
2. 阅读 [reference.md](reference.md)，计算约定总工时、预计加班工资、固定出摊成本、营业额贡献率、保本营业额、固定成本负担率和连续提成率。
3. 执行冲突校验；有冲突则停止并向用户给出可调整项。
4. 选择连续提成结构。档位用于展示进度，不设置整档跳发。
5. 先形成一份单一计算数据，再从同一数据生成 MD 和 PDF，禁止分别手算。
6. 将结果写入 `兼职方案/[市集名称]/`。
7. 生成兼职版临时 HTML；将 [poster.css](poster.css) 复制到输出目录或内联进 HTML，再用 `scripts/render-pdf.ps1` 导出 PDF 和逐页预览图。
8. 对照 MD 抽查数字，逐页检查 PDF，确认无敏感信息、截断、重叠和异常空白。

高质量参考见 [examples.md](examples.md)。不要机械复制示例中的金额或档位。

## 冲突校验

正式设计前必须检查：

1. 商品毛利率是否高于主办方营业额抽成比例，即营业额贡献率是否大于0；
2. 固定出摊成本、底薪和预计加班工资是否均为非负数；
3. 预计总营业额是否高于保本营业额；不高于时，说明预计经营亏损且目标内没有提成空间；
4. 固定成本负担率是否达到或超过100%；达到时自动提成率为0；
5. 自动提成率是否处于0%至5%之间，且低于营业额贡献率；
6. 约定总工时、日期数量和每日排班是否一致；
7. 提成是否只对超过保本营业额的部分连续计提；
8. 提成后每增加一元营业额是否仍能增加经营结余。

若校验失败：

- 不生成看似完整但数学上不可行的方案；
- 列出冲突数字；
- 给出“调整底薪、预计营业额、摊位费、装置费用、物流费用、主办方抽成或商品成本率”等选项；
- 等用户确认后再继续。

## 薪酬设计原则

- 默认采用“全勤底薪＋连续销售提成”。
- 优先使用简单的连续提成率，确保兼职容易理解、店主容易核算。
- 可设置保本、标准、冲刺等进度档，但档内必须连续计提。
- 不设置“差一元就少拿整档奖金”的断崖。
- 销售提成只计算超过保本营业额的部分，默认最高提成率为营业额的5%。
- 固定出摊成本负担越高，自动提成率越低；达到预计营业额后继续按同一提成率计提，不封顶。
- 加班工资独立于底薪和销售提成，最终应付工资＝底薪＋销售提成＋加班工资。
- 未全勤时，默认按“底薪折合时薪 × 实际计薪工时”支付底薪；已产生的销售提成正常结算。
- 金额计算保留两位小数；对外结算规则可约定四舍五入到元，但测算表保留原始口径。

## 店主版 Markdown

文件名：

```text
[市集名称]-兼职薪酬方案.md
```

至少包含：

1. 项目情况和排班；
2. 推荐薪酬结构、加班计费规则和一句话规则；
3. 提成公式、起提线及设计理由；
4. 至少四个工资计算示例；
5. 不同营业额下的工资、综合时薪、商品成本、固定出摊成本、经营结余和是否保本；
6. 每日保本、标准和冲刺参考目标；
7. 超过预计目标后的持续激励；
8. 工作内容和销售执行要求；
9. 行为红线及已确认的扣款口径；
10. 业绩统计和结算口径；
11. 可直接发布的招聘文案，并包含招募自我介绍要求；
12. 低营业额时的亏损风险说明。

店主版可以显示商品成本率、毛利率、摊位费、装置费用、物流费用、主办方抽成、保本营业额、经营结余和内部推导。

## 兼职版 PDF

文件名：

```text
[市集名称]-兼职薪酬说明.pdf
```

PDF 采用信息允许清单，只显示：

- 市集名称、日期、每日约定排班和加班时薪；
- 全勤底薪；
- 保本起提线、提成率和提成公式；
- 三至四个工资示例；
- 每日保本、标准、冲刺目标；
- 全勤要求；
- 工作内容和销售职责；
- 行为红线及已确认的扣款口径；
- 业绩统计与结算方式。

PDF 严禁显示：

- 商品成本率或毛利率；
- 摊位费、装置费用、物流费用或主办方抽成比例；
- 固定成本负担率、保本线内部推导或经营结余；
- 内部预算和经营风险；
- 提成公式的内部成本推导；
- “店主最多承受多少”等内部表述。

视觉要求：

- 市集活动海报风格，竖屏 1080×1920 比例，可多页；
- 使用微软雅黑等 Windows 常见中文字体；
- 重点突出底薪、每日目标和提成规则；
- 表格过宽时改为卡片或分表；
- 禁止渐变、表情符号、文字截断、表格溢出和卡片跨页；
- PDF 只面向兼职，不附店主经营测算。

## PDF 导出

生成临时 HTML 后执行：

```powershell
powershell -ExecutionPolicy Bypass -File ".cursor/skills/market-part-time-pay/scripts/render-pdf.ps1" `
  -HtmlPath "兼职方案/[市集名称]/[市集名称]-兼职薪酬说明.print.html" `
  -PdfPath "兼职方案/[市集名称]/[市集名称]-兼职薪酬说明.pdf" `
  -PageCount 4 `
  -PreviewDirectory "兼职方案/[市集名称]/_preview"
```

HTML 每个页面使用 `.screen`，并加入以下逻辑，使 `?p=0` 只显示指定页：

```html
<script>
  const page = new URLSearchParams(location.search).get("p");
  if (page !== null) {
    addEventListener("DOMContentLoaded", () => {
      document.querySelectorAll(".screen").forEach((el, i) => {
        el.style.display = String(i) === page ? "flex" : "none";
      });
    });
  }
</script>
```

验证完成后，可删除临时 HTML 和 `_preview`；最终至少保留 MD 与 PDF。

## 质量验收

- MD 与 PDF 来自同一组计算结果。
- 重新计算约定总工时、固定出摊成本、营业额贡献率、保本营业额、固定成本负担率、提成率和已知加班工资。
- 抽查至少三个营业额场景。
- PDF 文件存在且大小不为零。
- 逐页预览中没有截断、重叠、过宽表格或异常空白。
- PDF 包含工作内容和行为红线，且不包含经营敏感信息。
- 不声称方案满足当地最低工资或用工法律要求。
- 用户要求合规分析时，另行查询活动所在地的最新官方规定。
