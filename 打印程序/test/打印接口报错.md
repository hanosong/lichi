# `/api/print` 报错

## 现象

在标签管理里点「确认打印」后：

- 浏览器 Network 里 `POST /api/print` 显示失败（连接被重置、代理错误，或请求未完成）
- 页面 toast 报错
- 易联云侧其实已经接单，打印机可能已经出纸
- 本地 `data/database.json` 里也能看到对应的打印记录

也就是说：**云端打印成功了，HTTP 响应没回来。**

## 原因

`POST /api/print` 的顺序是：

1. 调用易联云 `print/index` 提交任务
2. 把打印记录写入 `data/database.json`
3. 再 `res.json(...)` 把结果返回给前端

开发脚本原先是：

```json
"dev": "concurrently -k \"npm:dev:server\" \"npm:dev:web\"",
"dev:server": "node --watch server/index.js"
```

`node --watch` 会监视整个项目目录。第 2 步一写 `database.json`，Windows 上的 `fs.watch` 会拿到空路径，Node 18 直接崩掉：

```
TypeError [ERR_INVALID_ARG_TYPE]: The "paths[1]" argument must be of type string. Received null
    at resolve (node:path:167:9)
    at FSWatcher.<anonymous> (node:internal/watch_mode/files_watcher:98:30)
```

进程在 `res.json` 之前退出，前端只能看到接口失败。  
`concurrently -k` 还会把已经挂掉的后端连带前端一起杀掉，页面随后也无法继续请求。

这不是易联云凭据错误，也不是打印内容格式错误。

## 处理

| 改动 | 目的 |
| --- | --- |
| `--watch` 改成 `--watch-path=./server` | 只监视服务端代码，写入 `data/database.json` 不再重启或打崩 Node |
| 去掉 concurrently 的 `-k` | 后端挂了时不要把 Vite 一起杀掉 |
| `fail()` 增加 `console.error` | 以后接口真失败时，终端能看到原因 |

当前脚本：

```json
"dev": "concurrently \"npm:dev:server\" \"npm:dev:web\"",
"dev:server": "node --watch-path=./server --watch-preserve-output server/index.js"
```

涉及文件：

- `package.json`：开发监听范围、concurrently 行为
- `server/index.js`：接口失败日志

## 验证

1. 用 `npm run dev` 启动后，打印一张标签。
2. 浏览器里 `POST /api/print` 应返回 200，body 里易联云 `error` 为 `0`。
3. 终端不应再出现 `ERR_INVALID_ARG_TYPE` / `paths[1]`。
4. `data/database.json` 的 `printRecords` 会新增一条，且服务进程还在。

## 以后注意

- 开发时不要让 `--watch` 监视会频繁写入的数据文件（`data/`、日志等）。
- 判断打印是否成功，要同时看：HTTP 是否 200、易联云返回、打印机是否出纸。三者可能不一致。
- 生产环境用 `npm start`（`node server/index.js`），没有 watch，不会触发这个问题。
